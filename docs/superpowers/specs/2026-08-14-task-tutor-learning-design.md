# 任务内 AI 导师学习设计

日期：2026-08-14

## 目标

让用户无需离开 PlanAgent，即可在每个学习任务中接受 DeepSeek 的自适应辅导。导师先诊断用户基础，再分段讲解、举例、提问和纠错，并在覆盖核心知识后建议进入现有检验。学习过程可中断、可恢复；只有通过现有 70 分检验，任务才自动完成。

## 范围

第一版只服务 `learn` 类型任务，使用 DeepSeek 的通用知识和当前任务上下文。它不包含全局导师、联网检索、资料上传、语音、多人会话、会话重置或新的任务完成规则。`practice` 和 `project` 继续使用现有交付检验。

本功能不使用 LangGraph。教学阶段和状态由普通服务层、严格的模型响应结构及数据库记录管理，减少新依赖和维护复杂度。

## 用户入口与页面

每日任务页中，未开始学习会话的 `learn` 任务显示“开始学习”，已有会话时显示“继续学习”。点击后进入独立路由 `/tasks/:taskId/learn`。

学习页使用独立双栏布局：

- 顶部显示任务标题、“返回每日任务”和“开始检验”。
- 左侧显示预计学习时长、当前教学阶段、已覆盖知识点和待加强知识点。
- 右侧显示完整对话历史、消息输入框和发送状态。
- 不显示未经验证的掌握百分比。
- 手机端把左侧内容折叠为对话上方的状态卡。

Agent 判断核心知识已覆盖时，页面显示“建议开始检验”。用户无论是否出现该提示，都可以主动开始检验。检验复用现有 `VerificationModal` 和评分契约；只有检验通过才完成任务。

## 教学流程

教学阶段为：

1. `diagnose`：通过一个简短问题判断用户已有理解。
2. `explain`：根据诊断结果分段讲解定义、边界和关键知识点。
3. `practice`：使用例子、反例或小练习要求用户应用知识。
4. `remediate`：针对误解或薄弱点重新解释和追问。
5. `ready`：核心知识已覆盖，建议进入检验。

阶段不是机械的单向进度条。用户回答暴露新误解时，可以从 `practice` 返回 `remediate`；一旦达到 `ready`，建议检验状态保持为真，用户仍可继续提问。

任务的 `estimated_hours` 是教学节奏预算。提示词据此控制知识点数量、讲解深度和练习轮数，但不启动倒计时，也不在预算耗尽时强制结束会话。

用户可以在任何阶段自由提问。用户消息始终作为普通对话内容，不能覆盖系统教学规则、任务边界或输出结构。

## 数据模型

### LearningSession

每个任务最多有一个学习会话：

- `id`
- `task_id`，唯一外键
- `stage`：`diagnose | explain | practice | remediate | ready`
- `session_summary`：供后续模型调用使用的滚动摘要
- `covered_points`：已覆盖知识点 JSON 数组
- `weak_points`：待加强知识点 JSON 数组
- `ready_for_verification`：布尔值，达到后保持为真
- `estimated_hours_snapshot`：开始学习时的预计时长快照
- `created_at`、`updated_at`

### LearningTurn

每行表示一个完整的用户—导师交换；首次诊断轮的 `user_message` 为空：

- `id`
- `session_id` 外键
- `client_turn_id`：会话内唯一，用于幂等重试
- `user_message`：首次诊断可为空
- `assistant_message`
- `stage`
- `created_at`

完整对话永久保存在 `LearningTurn` 中。模型调用只发送 `session_summary` 和最近 12 轮，避免长会话无限增长上下文和成本。

## 模型输出契约

每轮 DeepSeek 必须返回严格结构：

- `reply`：非空导师回复
- `stage`：合法教学阶段
- `session_summary`：对旧上下文的简洁更新摘要
- `covered_points`：非空字符串组成的去重数组
- `weak_points`：非空字符串组成的去重数组
- `ready_for_verification`：布尔值

服务端校验阶段与准备状态的一致性：`stage == ready` 时准备状态必须为真；准备状态一旦为真，不允许后续响应将其改回假。

空响应、畸形 JSON、Schema 不匹配或状态不一致均视为无效输出。每个教学轮最多调用 DeepSeek 三次，重试反馈只包含服务端生成的安全说明，不回显原始模型内容或异常文本。

## API 与事务

### `GET /api/tasks/{task_id}/learning-session`

读取已有会话和完整对话。尚未开始时返回 404；非 `learn` 任务返回 422。响应同时包含返回每日任务页所需的 `goal_id`。

### `POST /api/tasks/{task_id}/learning-session`

幂等地开始学习。若会话已存在则直接返回；否则先生成初始诊断，再在一个事务中写入会话和首轮导师消息。生成或持久化失败时不留下空会话或半条消息。

### `POST /api/tasks/{task_id}/learning-session/turns`

请求包含 `client_turn_id` 和非空 `message`。服务端读取摘要与最近 12 轮，生成并校验导师回复，然后在一个事务中写入本轮和更新会话状态。

同一 `client_turn_id` 的重试返回已经保存的结果，不再次调用模型。若模型或数据库失败，本轮不写入；API 返回稳定的 502，且不得包含模型原文、数据库参数或内部异常。前端保留输入并允许重试。

## 前端状态

- 首次进入：显示“导师正在准备诊断问题”，成功后展示第一条导师消息。
- 恢复会话：先加载历史消息和当前阶段，再启用输入框。
- 发送消息：禁用重复提交，显示“导师正在思考”。
- 失败：在当前输入附近显示错误和“重试”，保留原始输入及 `client_turn_id`。
- 准备检验：显示醒目但非强制的提示；“开始检验”始终可用。
- 检验通过：沿用现有逻辑完成任务并刷新每日任务状态。

导师回复按安全 Markdown 渲染，支持段落、列表和代码块，不执行原始 HTML 或脚本。

## 错误与一致性

- 任务不存在返回 404；非学习任务返回 422；空消息返回 422。
- DeepSeek 失败或三次无效输出返回稳定 502，不创建部分数据。
- 数据库 flush、refresh 或 commit 失败必须 rollback，会话仍可继续使用。
- 幂等键阻止网络重试造成重复回复。
- 完整历史是审计和恢复来源；滚动摘要只是模型上下文，不替代原始记录。
- Agent 的准备状态不改变现有检验隐私、10 题组成、评分或 70 分通过规则。

## 测试与验收

后端测试覆盖：

- 首次诊断创建与 `learn` 类型限制。
- 阶段推进、纠错回退和准备状态保持。
- 严格模型结构及最多三次重试。
- 最近 12 轮加滚动摘要的上下文构造。
- 会话恢复、完整历史和幂等 `client_turn_id`。
- 模型失败、flush/refresh/commit 失败的零部分写入与可复用会话。
- 稳定错误响应不泄露模型内容或数据库参数。

前端测试覆盖：

- “开始学习”与“继续学习”入口。
- 首次加载、历史恢复、发送中状态和失败重试。
- 独立双栏布局、移动状态卡及安全 Markdown。
- 已覆盖/待加强知识点和“建议开始检验”。
- 从学习页打开现有检验，只有通过后完成任务。

端到端验收使用一个真实学习任务确认：首次诊断会根据回答调整讲解；刷新页面后恢复原对话；失败重试不产生重复轮次；达到准备状态后可进入检验；未通过不完成任务，通过后显示现有完成勾选。
